The mshell type checker reads a script before it runs and rejects programs that would fail with a type error: adding a string to a number, reading a field a dictionary does not have, writing a string into a list of integers. It does not change what any word does at run time. A program behaves the same with the checker or without it; the checker only accepts or rejects.

Running the Checker § Back to top

Every script is type-checked before it runs, whether it is a file, -c code, or code read from standard input. When the check fails, nothing in the script runs. There is no way to run a script without checking it. Use --type-check-only to check the script and exit without running it. 

msh script.msh
msh --type-check-only script.msh

The checker checks every definition body in the file, and the code outside definitions. It also checks the standard library and the startup file, on every run. A definition there whose signature or body has a type error is still defined, but code that calls it is refused, with the error. A script that does not call it runs, and the errors are printed as a warning.

The startup files' top-level code, the code outside their definitions, is checked before it runs, and runs only if it checks. The script is checked from where that code leaves off: a variable the startup file sets, or a value it leaves on the stack, has its type in the script. If the startup file's top-level code does not check, it is not run, its errors are printed, and no script runs until it is fixed. --type-check-only checks the startup files' top-level code without running it.

When the file being checked is the startup file itself, it is checked as the program, with only the standard library before it. The language server runs the same checker on every edit, after the startup files' top-level code.

In error messages, _ stands for a type the checker has not worked out yet: after [] l!, the list's type is [_] until something fixes its elements.

In the Interactive Shell §

The interactive shell checks each line before it runs it. A line that does not check is not run, and changes nothing: its errors are printed, and the next line starts where the line before it left off. What a line leaves behind carries over to the next: the types of the values on the stack, variables, definitions, and type and enum declarations. 

[] l!
@l 1 append drop       # l is a list of ints from here on
@l "a" append drop     # refused: 'append' expected int

The same goes for a quotation whose input a later line decides, as a later word would in a file: 

(len) q!
"abc" @q x wl          # q takes a str from here on

A line that checks can still stop with an error, such as an index out of range or ? on none. The stack then goes back to what it was before the line, except new lists, dictionaries and grids the line took from the stack, which are dropped, since the line may have changed them. What the line did to stored values and variables stays.

return at the top level of a line ends the session, as it ends a script. Type errors in the startup files' definitions are printed once when the shell starts, and a line that calls such a definition is refused. The startup files' top-level code is checked as the session's first lines: the shell starts with the types of the values and variables it leaves. If it does not check, it is not run, its errors are printed, and the shell starts without it.

Stack Effects § Back to top

A definition's signature says what it takes from the stack and what it leaves. Inputs come before --, outputs after it. The rightmost input is the top of the stack. 

def addOne (int -- int)
    1 +
end

def fullName (str str -- str)
    last! first!
    $"{@first} {@last}"
end

A single letter in a signature, optionally followed by digits (a, T, T1), is a generic: the same name means the same type everywhere in that signature, and the body cannot assume anything about it. Any other name must be a type, so a misspelled type, or one mshell spells differently (string for str, numeric for int | float), is an error. 

def first ([a] -- a)
    :0:
end

def applyTwice (a (a -- a) -- a)
    f!
    @f x
    @f x
end

In a signature, dict is short for {T} and list for [T], each with a generic T of its own. Outside a signature, write the full form.

Definitions That Never Return §

A definition that always stops the script, or loops forever, says so with never as its whole output side. Then a branch that calls it does not need to leave anything. 

def die (str -- never)
    wle 1 exit
end

true if 5 else "bad" die end 1 + wl

never is only allowed as the whole output side of a signature or quotation type. A definition that stops on some paths and returns on others declares what it returns when it returns: (bool -- never | str) is an error.

New Outputs §

An output marked new is a list, dictionary or grid that nothing else refers to (see New Values), so the caller may give it another type. The mark must match the body exactly: new on an output the body may share is an error, and so is a missing new on an output that is new on every path. The language server offers both fixes. 

def loadConfig (-- new Json)
    "config.json" readFile parseJson
end

loadConfig tryAs {name: str} ? :name? wl

Type Expressions § Back to top

The base types are int, float, bool, str, path, datetime, binary and null. null is the JSON null. It is different from none, the empty Maybe, which is a value and not a type. Use int | null for an integer or a JSON null, and Maybe[int] for an integer that may be missing.

Form Meaning Example
T A base type, an alias, an enum, or a generic int, Person, a
[T] A list whose elements are all T [str], [int | str]
{T} A dictionary whose values are all T, with any keys {int}
{a: T, b?: U} A dictionary shape: a is present, b may be missing, other keys may hold anything {name: str, age?: int}
{a: T, *: U} A shape whose other keys hold U {url: str, *: int}
Maybe[T] just a T, or none Maybe[int]
T | U A union: a T or a U, which must be of different kinds int | float | null
(A B -- C) A quotation that takes an A and a B and leaves a C (int int -- bool)
E[T] An instance of a generic enum Box[int]
Grid, GridView, GridRow A grid whose columns are not known (see Grids) Grid

Type Aliases §

type Name = T gives a type a name. The name and the type are interchangeable everywhere; the name makes signatures and error messages shorter. An alias may refer to itself, as long as every path back to it passes through a list, dictionary, field, quotation or enum. 

type Person = {name: str, age: int, friends: [Person]}
type Cell = int | float | str | bool | null

type A = A and type A = int | A are errors: they do not say what a value looks like. Enums, the other kind of declaration, are described in Data Types.

Some aliases are built in. Json is every value parseJson can give: null | bool | int | float | str | [Json] | {Json}. HtmlNode is what parseHtml gives. The dictionaries other built-in functions take and give have names too, so a stored one can be given its type where it is made: HttpRequest, HttpResponse, Cookie, PackEntry, TarDest, ExtractOptions, ExtractEntryOptions, ZipEntryInfo, TarEntryInfo, NumFmtOptions, Link, EnvEvent, CompletionResult and PromptInfo. The enums of the interactive prompt are built in too: PromptItem, Base16Color, BaseBrightness, TextAttribute and CursorShape (see Customizing the Prompt). UrlEncodable, str | path | int | [str | path | int], is what urlEncode writes from each value of a dictionary. 

[`a.txt` {path: "b.txt", archivePath: "docs/b.txt"}] as [PackEntry] entries!
@entries "out.zip" zipPack

Ascription with as §

value as T tells the checker to treat the value as a T. It does nothing at run time, so it needs evidence: the value's type must already fit T, as an int fits int | str. A new value may also be given a wider type, such as a list literal given a wider element type. For data from outside the script, which no static type describes, use tryAs. 

5 as int | str          # ok: an int is an int | str
[1 2] as [int | str]    # ok: a new list may be given a wider type
"a" parseJson as Json   # ok: parseJson gives Json
"5" parseJson as int    # error: a Json may be any kind of value; use tryAs

Unions § Back to top

The members of a union must be of different kinds. The kinds are: each base type, list, dictionary, quotation, Maybe, each enum, and Grid, GridView and GridRow. So int | [str] and str | {int} | null are unions, while [int] | [str], {a: int} | {b: str} and Box[int] | Box[str] are errors. A generic cannot be a member, since it could be any kind. For two lists or two shapes, declare an enum: 

enum Ids = ints [int] | strs [str] end

A union is taken apart with match by kind. Each kind identifies one member, so the name it binds has that member's type exactly, and it can be written through. 

def total (int | [int] -- int)
    match
        int n : @n,
        list xs : @xs sum,
    end
end

New Values and Stored Values § Back to top

Lists, dictionaries and grids are shared, not copied: storing a list in two variables gives two names for one list, and writing through either one changes it. That is why a list that is already stored cannot be given a different type. If xs holds a [int] and the checker let @xs as [int | str] through, a string could be appended through the new name, and code reading xs as integers would get a string. 

[1 2] xs!
@xs as [int | str] ys!   # error: xs is stored, so its list keeps its type

A value nothing else refers to yet is new. A new value may be given any type it fits, because nobody else can see the change. New values come from literals of new values, and from words that make them: parseJson, lines, split, parseCsv, deepCopy, and the others marked new in their signatures. A value stops being new when it is stored, passed to a definition, put in another list or dictionary, or duplicated with dup. 

[1 2] as [int | str] xs!       # ok: the literal is new
@xs "three" append drop

Words that make a new list from the elements of another, such as map, filter, take, skip, reverse, sort and slices, give a new list when its elements hold no list or dictionary. Otherwise the elements are still stored somewhere else, and the result is stored too.

A literal around a stored value is new on the outside only: {a: @xs} is a new dictionary holding the stored list xs. The dictionary may gain optional keys, but xs keeps its type. 

[1] xs!
{a: @xs} as {a: [int], b?: int}         # ok: only the dictionary changes type
{a: @xs} as {a: [int | str]}            # error: xs keeps its type

Copies §

deepCopy makes a new value from a stored one: every list, dictionary and grid inside it is copied, once for each path that reaches it. Strings, numbers and other values that cannot change are shared, so copying a list of strings is cheap. A value that contains itself cannot be copied: deepCopy stops with an error naming the cycle. 

[1 2] xs!
@xs deepCopy as [int | str] ys!   # ok: ys is a different list
@ys "three" append drop

The checker never copies anything itself. Where a program needs a copy, the error says so, and the program writes deepCopy.

Changing a Type in Place §

Some words change a value's type where it is: a redirect changes where a command's output goes, and updateCol can change a grid column's type. These need a new value. Writing the redirect straight after the list literal, or updating a grid straight from parseCsv and toGrid, is new; on a stored value they are errors that suggest deepCopy. The literal may hold stored values, such as a stored list of arguments ([grep @flags "x"] *): the redirect changes only the new list. 

[echo "hi"] * ; out!            # ok: the literal is new
[echo "hi"] c!
@c * ;                          # error: c is stored
@c deepCopy * ;                 # ok

Validating Data § Back to top

as does nothing at run time, so it cannot say what data from outside the script holds. tryAs T checks at run time that the value on top of the stack conforms to T. It replaces the value with just the same value when it does, and with none when it does not. The value is checked in place, not copied, and nothing about it changes. 

type Person = {name: str, age: int}

'[{"name": "Ada", "age": 36}]' parseJson tryAs [Person] match
    just people : @people (:age?) map sum wl,
    none : "not a list of people" wl,
end

Every part of the value is checked: each element of a list, each value of a dictionary, each payload of an enum value. A written shape type allows keys it does not name, and an optional field may be missing. A recursive type such as Json checks the whole value, and a value that contains itself conforms to a type it has. A match arm can check a type too, with is T name.

A quotation cannot be looked inside, so T cannot be a quotation type or an enum that holds one, and a def's generic is not known at run time. Checking a very large value stops with an error, not none, after 67,108,864 (1 << 26) steps.

tryAs on a new value, such as the result of parseJson, may check it against any type. A stored value, or a def's input, can only be checked against a type it already has, or one with no list or dictionary in it, because after the check the same list or dictionary would have two types. Check the value where it is made (parseJson tryAs T ?), or check a copy (deepCopy tryAs T).

Dictionaries § Back to top

A dictionary has string keys. Its type is either a homogeneous dictionary, where every value has one type and keys come and go, or a shape, where specific keys have specific types.

Homogeneous Dictionaries §

{T} is for dynamic keys: a count table, an index by name. Any key may be read, written or deleted. 

{} as {int} counts!
@counts "passed" 10 setd
@counts "passed" get 0 maybe wl

The long form {str: T} is the same type, as is {*: T}. Error messages show the long form.

Dictionary Shapes §

A shape is for a dictionary used as a record. Each field has its own type, and :field? reads it at that type. Without ?, a read gives Maybe[T]. 

def label ({name: str, age: int} -- str)
    person!
    $"{@person :name?} ({@person :age? str})"
end

A written shape type says nothing about the keys it does not name: a {name: str} may have other keys, of any type. A shape literal's own type is exact: {name: "Ada"} has the key name and no other. Error messages and hover show it as exact {name: str}; no type you write is exact. *: T says the other keys hold T: {url: str, *: int}.

A field written name?: T is optional: the key may be missing, and when present it holds a T. This is different from Maybe: timeout?: int says the key may be missing, timeout: Maybe[int] says the key is there and its value may be none. 

type Request = {url: str, timeout?: int}

{url: "x"} as Request                  # ok: timeout missing
{url: "x", timeout: 30} as Request     # ok
{url: "x", timeout: "soon"} as Request # error: timeout must be an int
{timeout: 30} as Request               # error: url is missing

A shape fits another shape that names fewer of its fields, with the same field types. A value whose type does not mention an optional key fits timeout?: int only when the value is new: a stored one could be seen through another name that says the key is absent. Option dictionaries written as literals where they are used are always new.

A shape never fits {T}: through a homogeneous dictionary any key could be deleted or set to a T, which the shape's other names would not expect. A {T} fits a shape only when all its fields are optional and of type T. To turn one into the other, write the value as a literal, copy it with deepCopy, or check it with tryAs.

Reading and Writing by Key §

With a string literal written right before it, get reads that field, like :field. With a key known only at run time, the key could name any field, so get gives a Maybe of a type that covers every field: int | str for a {a: int, b: str}, and an unknown type for a written shape, whose other keys may hold anything. Words that only read a dictionary, such as keys, values, in and len, take shapes as well as {T}.

set with a literal key writes a field at its declared type. Words that write a key known only at run time (setd, and set with such a key) or delete one (del) need a {T}. A new dictionary may gain keys: {} "name" "Ada" set "age" 36 set builds a {name: str, age: int}.

Lists § Back to top

A list type has one element type. [int] is a list of integers, and [int | str] a list whose elements are each an integer or a string. Generic words keep the element type: map, filter, sortByCmp and indexing. 

def doubleAll ([int] -- new [int])
    (2 *) map
end

def adults ([{name: str, age: int}] -- [{name: str, age: int}])
    (:age? 18 >=) filter
end

doubleAll's output is marked new because map makes a new list of integers; see New Outputs. A list literal's type is the join of its elements: [1 "Ada" true] is a [int | str | bool]. The checker does not track the type at each position, so :0: on that list gives an int | str | bool.

A stored [int] does not fit a parameter of type [int | str]: the definition could append a string. Give the list its wide type where it is made, or pass a copy. A word that only reads a list is typed with a generic ([a]), so it takes any list.

Grids § Back to top

A grid's type includes the type of each column, like a shape of columns. The checker works it out from grid literals and from words such as select, derive and groupBy; there is no syntax to write it. Reading a column by a literal name gives that column's type, and reading a column the grid does not have is an error. 

[| name, score; "Ada", 90; "Bob", 70 |] g!
@g "score" gridCol sum wl
@g "upper" {} (:name? upper) derive "upper" gridCol str wl

A grid whose columns are not known, written Grid in a signature, or made by toGrid, can be read but not written, and its cells are of unknown type. Use select to take the columns you need.

Writing a cell or a column keeps its type on any grid. Changing a column's type (updateCol with a quotation that gives another type, extend with wider cells), or adding, removing or renaming a column, needs a new grid: on a stored one it is an error that suggests deepCopy. A grid straight from a literal, parseCsv or toGrid is new. 

[| x; 1; 2 |] "x" (str) updateCol g!   # ok: the literal is new
@g "x" (len) updateCol drop             # error: g is stored

Quotations § Back to top

A quotation type is the stack effect of the code inside it. A quotation literal given to a word that takes one, such as map, filter, each or a definition with a quotation parameter, is checked against what the word gives it, after the word's other arguments are known. In @xs (1 +) map, map knows the element type from @xs.

A stored quotation is typed on its own. An overloaded word inside it, such as +, is decided by how the quotation is used later; if nothing decides it, the checker asks for an annotation. 

(1 +) inc!
5 @inc x wl       # ok: the use decides that + is (int int -- int)

x needs to know how many values a quotation takes and leaves. Quotation parameters of definitions have written types, so this is only a question for a quotation whose type cannot be worked out.

break and continue are allowed only where they are checked: in a loop body, and in a quotation literal given to each, map or a similar word inside one. A stored quotation cannot break: it could be run where no loop is running. each, map on a list, and the other words that run a quotation once per element give it a stack of its own, which a break throws away. map on a Maybe, bind and map2 run it on the current stack, so the loop is left with what the quotation pushed so far, and that must match the loop's stack.

Control Flow § Back to top

Joining Branches §

The arms of an if, iff or match must leave the same number of values. Where they leave different types, the result is their join:

Arms leave Result
1 / 2.5int | float
none / 5 justMaybe[int]
[1] / ["a"] (new)[int | str]
{a: 1} / {a: 2, b: 3} (new){a: int, b?: int}
a stored [int] / a stored [str]error: neither list may change type
1 / 1 exitint: an arm that never returns is left out
5 / "x" parseJsonJson
(2 *) / (1 + str)error: write the quotation type both fit with as in each arm

When a later word does not take a union that a join made, the error says which arm left which member.

Variables §

A variable has one type in its scope (a definition body, or the code outside definitions): the type of its first store. A later store of a value that does not fit is an error; use a new name, or give the first store the wider type with as. none fixes nothing: after none r!, 5 just r! makes r a Maybe[int]. 

1 as int | str x!
"a" x!                 # ok: x is an int | str

A variable must be set on every path before it is read. A store in an if arm counts after the if only when every arm that goes on stores it. A store in a quotation counts only where the quotation runs right away: an iff, loop or x on a literal.

The names a match arm binds are variables of the enclosing scope, so two arms that bind one name must bind it at one type: write int n and str s, not int n and str n.

Values of Unknown Type §

Some values have a type the checker does not know: a field a written shape does not name, a cell of a grid whose columns are unknown. A match by kind tells what kind of value it is, but not what is inside it. A list of unknown elements can be measured, iterated and reordered, but nothing can be assumed about its elements, and it cannot be bound to a name that outlives the arm. Keep it on the stack with :>, or check it with tryAs or is first.

An error about a value of unknown type names the read that made it, and why. A get with a key known only at run time is a common one: on a {name: str}, the key may name a field the shape does not declare. Say what those fields hold with *: T, as in {name: str, *: str}, or use {str}.

Overloaded Words on Unions §

An overloaded built-in given a union is checked once for each member. It checks when every member is handled, and its result is the join of the results. 

true if 1.0 else 1 end toFloat   # float: (int -- float) and (float -- float)
true if 1.0 else 1 end 2.0 /     # error: the int member has no (int float) form

Current Boundaries § Back to top

A program that checks can still stop with an error that depends on the data: an index out of range, ? on none, a missing file, a command that fails, exit, a division by zero. These are visible in the types (a Maybe, a command) or come from outside the script. For data from outside, declare a type and check the data against it with tryAs where it enters the script; the rest of the script is then checked against that type.
