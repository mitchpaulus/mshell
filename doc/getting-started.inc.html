Getting started with mshell is a quick setup: install the CLI binary and then enable editor support.

Installation § Back to top

1) Download the binary and add it to your PATH

mshell ships as a single executable. Download the appropriate release archive from the GitHub releases page, extract it, and place the binary on your PATH.

Linux/macOS

tar -xvf linux_amd64.tar.gz
mv msh ~/.local/bin/
chmod +x ~/.local/bin/msh

Windows

# cmd.exe
tar -xvf windows_amd64.tar.gz
move msh.exe "%USERPROFILE%\\bin\\"

# PowerShell
tar -xvf windows_amd64.tar.gz
Move-Item msh.exe "$env:USERPROFILE\\bin\\"

2) Set up the standard library

Copy std.msh from the release into the startup location for the version of msh you are installing. msh looks for the standard library at $XDG_DATA_HOME/msh/<version>/std.msh on Linux/macOS (falling back to ~/.local/share/msh/<version>/std.msh) and at %LOCALAPPDATA%\msh\<version>\std.msh on Windows.

It also loads a user init file from $XDG_CONFIG_HOME/msh/<version>/init.msh on Linux/macOS (falling back to ~/.config/msh/<version>/init.msh) or %LOCALAPPDATA%\msh\<version>\init.msh on Windows.

To open the current init file without remembering the path, run msh edit init. It uses $EDITOR when available, otherwise the platform default opener.

The standard library is required at the resolved path. For interactive use and scripts without VER, missing init.msh is allowed unless you explicitly set MSHINIT. Scripts with VER "vX.Y.Z" require the version-specific init.msh for that version. If you need to override startup for a specific run, MSHSTDLIB and MSHINIT take precedence for interactive use and scripts without VER. Scripts with VER "vX.Y.Z" always use the version-specific startup files for that version.

An example installer script is available at install.sh.

Customizing the Prompt § Back to top

The interactive shell's prompt is set in init.msh with setPrompt. It takes a quotation that is given a PromptInfo and returns a list of PromptItem values. 

def myPrompt (PromptInfo -- new [PromptItem])
    info!
    @info :lastLineOk? (baseGreen) (baseRed) iff status!
    [
        pwd setWindowTitle
        baseBlue baseBright setFgColorBase16
        pwd promptText
        resetStyle
        $" ({@info :stackDepth?})" promptText
        promptNewline
        @status baseNormal setFgColorBase16
        ":: " promptText
        resetStyle
    ]
end

(myPrompt) setPrompt
steadyBar setCursorShape

The shell runs the quotation before every prompt. Text is shown as written, except that control characters, including newlines, are shown visibly (^[, ^J). Start a new line with promptNewline. Each color or attribute lasts until it is changed, and everything is reset before the command.

PromptItem Description
promptText str Prompt text with control characters sanitized.
promptNewline Start a new line.
setFgColorBase16 Base16Color BaseBrightness Text color from the terminal's 16 colors: baseBlack, baseRed, baseGreen, baseYellow, baseBlue, baseMagenta, baseCyan or baseWhite, and baseNormal or baseBright.
setFgColor256 int Text color from the 256 color palette, 0 to 255.
setFgColorRgb int int int Text color as red, green and blue, each 0 to 255.
setFgDefault The terminal's default text color.
setBgColorBase16, setBgColor256, setBgColorRgb, setBgDefault The same, for the background color.
setTextAttr TextAttribute Turn on attrBold, attrFaint, attrItalic, attrUnderline, attrBlinking, attrReverse, attrHidden or attrStrikethrough.
clearTextAttr TextAttribute Turn an attribute off. Bold and faint are turned off together.
resetStyle Turn off every color and attribute.
setWindowTitle str Set the terminal's window title.
promptHyperlink str str A URL and the text that links to it, in terminals that support links. Characters other than printable ASCII, and spaces, must be percent-encoded in the URL.

PromptInfo tells the prompt about the session:

Key Type Description
stackDepth int How many values are on the stack.
stackTypes [str] The type of each value on the stack, bottom first, such as ["int" "[str]"].
lastLineOk bool Whether the last line ran without an error. A line that does not parse or type check counts as an error.
lastExitCode Maybe[int] The exit code of the last command the last line ran, or none if it ran none.
lastDurationMs int How long the last line took, in milliseconds.

The prompt runs on its own stack, so it cannot change the values on yours.

If the prompt fails, takes longer than 3 seconds, or is interrupted with Ctrl-C, the shell stops it and shows the built-in prompt. A command the prompt is running is stopped too. The error is printed once, not again while the prompt keeps failing the same way.

setCursorShape sets the cursor's shape while the shell reads a command: blinkingBlock, steadyBlock, blinkingUnderline, steadyUnderline, blinkingBar or steadyBar. The terminal's own cursor is put back before each command runs, and when the shell exits.

These types and their members are built in, so their names cannot be used for your own types, members or definitions.

Abbreviations § Back to top

An abbreviation is a short word that the interactive shell expands into longer text as you type it. Abbreviations are added in init.msh with abbrAdd, which takes an Abbr. The common case is a word at the start of a command, expanded to text: with the first line below, typing s and Space gives git status -u . 

{abbr: 's' abbrWord, expansion: 'git status -u' abbrText} abbrAdd
{abbr: 'co' abbrWord, expansion: 'checkout' abbrText, position: ['git'] abbrArgOf} abbrAdd
{abbr: 'gcm' abbrWord, expansion: "git commit -m '%'" abbrText, cursorMarker: '%'} abbrAdd

# `..` is `'..' cd`, `...` is `'../..' cd`, and so on.
def upDirs (AbbrInfo -- Maybe[str])
    :word? len 1 - n!
    '..' @n repeat '/' join up!
    $"'{@up}' cd" just
end
{abbr: '\.\.+' abbrRegex, expansion: (upDirs) abbrFunc} abbrAdd

Space and the characters |, ;, <, >, ] and ) try the word that ends at the cursor, then insert the key, so [s] gives [git status -u]. Enter tries the word the cursor is in or at the end of, then runs the line, so a line runs expanded even if it would not parse unexpanded. Ctrl-Space inserts a space without expanding; to run a word as typed, press Ctrl-Space and then Enter. These keys are key bindings, so other keys can be made to expand too. Tab completion, history and pasted text do not expand. History gets the expanded line.

The word is the text back to the previous space or [ ] ( ) { } | ; < >. A word inside a string, path or comment never expands.

Key Type Description
abbr AbbrMatch The word to expand: abbrWord str, exactly this word, or abbrRegex str, any word the regular expression matches in full. Regular expressions use the same syntax as reMatch.
expansion AbbrExpansion What the word becomes: abbrText str, this text, or abbrFunc (AbbrInfo -- Maybe[str]), the text a quotation returns when the word is typed, or none to leave the word to the next abbreviation.
position (optional) AbbrPosition Where the word expands. abbrCommand, the default, is a command word: the start of the line, the head of a list ([s), or after | on a command line. abbrAnywhere is any word. abbrArgOf [str] is an argument of one of these commands, compared as written: the first word of the list the word is in, or of the command on a command line. A file after < or > is not an argument.
cursorMarker (optional) str Text in the expansion where the cursor goes. It is removed, and a Space that expanded the word is not inserted. Any length; with %, gcm and Space give git commit -m '|' with the cursor at |.
description (optional) str A note for yourself, which abbrList gives back.

An abbrFunc quotation is given an AbbrInfo:

Key Type Description
word str The word being expanded, as typed.
command Maybe[str] The command the word is an argument of, as for abbrArgOf, or none.
line str The whole command line, before the key that expanded the word.

The quotation runs on its own stack, so it cannot change the values on yours. If it fails or takes longer than 1 second, the word is left as typed, and the error is shown below the command line. Ctrl-C does not stop it; a key pressed while it runs is read after it ends. The error is shown once, not again while the quotation keeps failing the same way. What the quotation prints is not shown.

When several abbreviations apply to a word, the one added last is tried first. abbrAdd replaces an abbreviation with an equal abbr and an equal position, so l can be one command at the start of a line and another after jj. abbrErase removes every abbreviation with an abbr, and abbrRename renames them. abbrList gives them all, oldest first. To remove only one of several with the same abbr, take abbrList, erase the abbr, and add back the ones to keep.

None of these fails on a value of the right type. An abbreviation that can never expand, such as a word with a space, a regular expression that does not compile, or an empty abbrArgOf list, is added but never expands, and the interactive shell prints a warning about it.

Tab in command position offers the words of abbreviations that expand there.

These types and their members are built in, so their names cannot be used for your own types, members or definitions.

Key bindings § Back to top

Every key the interactive shell reacts to is a key binding: a sequence of keys, and what it does. The shell starts with the default keymap, and init.msh adds to it with bindingAdd, which takes a Binding. 

{keys: [r'j' r'f'], action: [editAccept] bindingOps, within: 150} bindingAdd
{keys: [r'v' r'l'], action: [editClearScreen] bindingOps, within: 150, idleBefore: 150} bindingAdd
{keys: [r'x' keyCtrl r'e' keyCtrl], action: [(editInEditor) editRunOps] bindingOps} bindingAdd
{keys: [keyF1], action: [([lf];) editRun] bindingOps} bindingAdd

# Put `sudo ` in front of the line, keeping the cursor where it was in the text.
def sudoLine (EditState -- new Maybe[[EditOp]])
    s!
    [$"sudo {@s :before?}" @s :after? editSetLine] just
end
{keys: [r's' keyAlt], action: (sudoLine) bindingFunc, description: 'sudo the line'} bindingAdd

With these, j and then f runs the line, v and l typed as a quick pair clears the screen, Ctrl-X Ctrl-E edits the line in your editor, F1 runs lf without losing what you had typed, and Alt-S puts sudo in front of the line.

Key Type Description
keys [Key] The keys to press, in order, at most 8.
action BindingAction What the keys do: bindingOps [EditOp], a fixed list of editor operations, or bindingFunc (EditState -- Maybe[[EditOp]]), a quotation that is given the line and returns the operations to run, or none to decline.
mode (optional) EditMode The keymap the binding is in: modeInsert, the default, or modeComplete, while Tab cycles through matches.
within (optional) int The longest time, in milliseconds, between two of its keys.
idleBefore (optional) int The shortest time, in milliseconds, with no key before its first key.
description (optional) str A note for yourself, which bindingList gives back.

Keys

A Key is one of three things.

  • A rune, for a key that types text, named by the text it types: r'j', r'J', r';', r'é', and r' ' for the space bar.
  • A NamedKey, for a key that types no text: keyEnter, keyTab, keyBackspace, keyEscape, keyDelete, keyInsert, keyUp, keyDown, keyLeft, keyRight, keyHome, keyEnd, keyPageUp, keyPageDown, keyF1, keyF2, keyF3, keyF4, keyF5, keyF6, keyF7, keyF8, keyF9, keyF10, keyF11, keyF12, keyF13, keyF14, keyF15, keyF16, keyF17, keyF18, keyF19, keyF20, keyF21, keyF22, keyF23, keyF24, keyF25, keyF26, keyF27, keyF28, keyF29, keyF30, keyF31, keyF32, keyF33, keyF34 and keyF35.
  • A ModifiedKey, a key held with keyCtrl, keyAlt, keyShift or keySuper. The modifier comes after the key, as with any enum member that holds a value: r'x' keyCtrl is Ctrl-X, r'r' keyShift keyAlt is Alt-Shift-R, and keyLeft keyAlt keyCtrl is Ctrl-Alt-Left.

A misspelled key is a type error: [r'x' ctlr] is not a [Key]. How a key is spelled does not matter. The order of the modifiers does not, and a repeated modifier counts once. A letter with Shift and nothing else is the capital letter, so r'j' keyShift is r'J'. With Ctrl, Alt or Super, a capital letter is the letter with Shift, so r'W' keyAlt is r'w' keyShift keyAlt. Shift on a key that is not a letter, such as r';' keyShift, never fires: the terminal sends the text the key types, r':', and which key that is depends on your keyboard layout.

Which keys the shell can tell apart depends on the terminal. Most terminals send keys in an old encoding in which some keys are the same: Tab is Ctrl-I, Enter is Ctrl-M, many terminals send Ctrl-H for Ctrl-Backspace, and Ctrl with Shift on a letter is Ctrl alone. In it, Alt and a key is sent as Escape and then the key, so the shell tells them apart by how they arrive. An Escape that arrives on its own is keyEscape, and acts when you press it. An Escape that arrives together with a key is Alt and that key when a binding uses it, and otherwise Escape and then the key. Nothing waits for a time: a terminal sends a key's bytes together, so this is right whether you type fast or slow, and over ssh. The file manager reads keys the same way.

Terminals that implement the kitty keyboard protocol (kitty, foot, ghostty, WezTerm, alacritty, iTerm2 and others) send every key distinctly. The shell asks the terminal for it when it starts, uses it while you edit a line, and turns it off before running anything. With it, Escape is keyEscape, Ctrl-I is not Tab, Ctrl-Shift-X can be bound, and Ctrl and Alt bindings follow the key's place on a US keyboard, so r'w' keyCtrl works on other layouts too. Set the environment variable MSH_KITTY_KEYS to 0 to keep the old encoding, for a terminal that implements the protocol badly. A binding for a key a terminal cannot send is not an error; it never fires there.

msh keys shows each key you press as a binding writes it, with the bytes the terminal sent and the time since the key before. Use it when a binding does not fire. Ctrl-C twice, or Ctrl-D, ends it. 

Reading keys (legacy encoding). Ctrl-C twice, or Ctrl-D, ends.
r'x' keyCtrl                             18
r':'                                     3a                       +401 ms
keyLeft keyAlt                           1b 5b 31 3b 33 44        +960 ms
r'x' keyAlt  (or keyEscape then r'x', when that is not bound) 1b 78           +512 ms

Editor operations

An EditOp is one thing the editor does. The operations of a binding run in order, and the line is drawn once after the last. The first group only changes the line and the cursor; these are edits.

Operation Does
editInsert str Insert the text at the cursor, with no abbreviation or binding.
editSelfInsert Insert the text of the last key of the sequence.
editSetLine str str Make the line the two strings joined, with the cursor between them.
editLeft, editRight Move the cursor one character.
editWordLeft, editWordRight Move the cursor one word.
editLineStart, editLineEnd Move the cursor to the start or end of the line.
editBackspace, editDelete Delete the character before or under the cursor.
editDeleteWordLeft Delete the word before the cursor.
editDeleteToStart, editDeleteToEnd Delete from the cursor to the start or end of the line.
editExpandAbbr Expand the abbreviation that ends at the cursor, if one applies.
editAccept Expand the abbreviation at the cursor and run the line. It must be the last operation.
editExit Leave the shell. It must be the last operation.
editRun ( -- ) Run the quotation with the terminal, and keep the line (below).
editRunOps (EditState -- Maybe[[EditOp]]) Run the quotation with the terminal, then run the operations it returns on the line (below).
editForward Move right, or at the end of the line accept the history suggestion.
editAcceptSuggestion Accept the history suggestion.
editHistoryPrev, editHistoryNext Go to the previous or next line in history.
editHistorySearchBack, editHistorySearchForward Search history backward or forward for lines that start with the text typed, ignoring case.
editLastArg Insert the last argument of the previous line; pressed again, of the line before that.
editComplete, editCompleteBack Complete the word at the cursor. With several matches, the shell enters modeComplete.
editCompleteNext, editCompletePrev Go to the next or previous match.
editCompleteLeft, editCompleteRight Go to the match in the column to the left or right.
editCompleteAccept Keep the match on the line and stop cycling.
editClearScreen Clear the screen.
editRemeasure Forget the measured widths of text and measure again. Use it after reattaching, changing fonts, or when the line looks wrong.
editMessage str Show the text below the line.

editRun runs a quotation as a command line runs: with the terminal, in the foreground, and with no time limit, so it can start an interactive program such as lf or fzf. It runs on its own stack, which it must leave empty, and it can change the directory. When it ends, the prompt is drawn again with the line and cursor as they were. It is not added to history, and the prompt still reports on the last line you ran. To have a key run something that goes into history, have it set and run a line instead: ['git status' '' editSetLine editAccept].

editRunOps is the same, but its quotation is given the line as an EditState, and returns the operations to run on it afterwards, or none to keep it. The standard library's editInEditor, on Ctrl-G, is one: it opens the line in $EDITOR (vi when that is not set) as a .msh file, and puts what you saved on the line, without running it. If the editor fails, the line is kept. To run the edited line at once, bind [(editInEditor) editRunOps editAccept].

Quotations

A bindingFunc quotation is given an EditState, and returns just the operations to run, or none to decline. When it declines, the keys act as if the binding were not there.

Key Type Description
before str The line before the cursor, as it was before the first key of the binding.
after str The line from the cursor on.
keys [Key] The keys that ran the binding, so one quotation can serve several keys.
mode EditMode The mode the keys were pressed in. 
# Run a quotation only when the line is empty; elsewhere the keys are typed as they are.
def onEmptyLine (EditState ( -- ) -- new Maybe[[EditOp]])
    s!, q!
    @s :before? @s :after? + '' = if [@q editRun] just else none end
end
{keys: [r';' r'r'], action: (([lf];) onEmptyLine) bindingFunc} bindingAdd

The quotation runs while you type, so it should be quick: like an abbreviation's quotation, it runs on its own stack and is stopped after 1 second. If it fails or is stopped, it declines, and the error is shown below the line, once while it keeps failing the same way. What it prints is not shown. Anything slow or interactive belongs in an editRun it returns. Operations it returns after editAccept or editExit are not run.

A binding is tested like any other definition, in a script, with an EditState made by hand. With sudoLine from the first example: 

{before: 'ab', after: 'cd', keys: [r's' keyAlt], mode: modeInsert} sudoLine str wl

Sequences and timing

Typing is never delayed. A key that begins a longer binding acts at once, so with [r'j' r'f'] bound, j appears as soon as it is typed. If f follows, the line goes back to what it was before the j, and the binding runs on that. Any other key after the j types itself as usual. A key that types nothing, such as Ctrl-X at the start of Ctrl-X Ctrl-E, shows the keys so far below the line (r'x' keyCtrl -), and a key that does not continue the sequence then acts on its own. When bindings of different lengths end at the same key, the longest one runs. Pasted text is never part of a binding, and ends any sequence.

Only edits can be taken back. A binding with any other operation, or with a quotation, runs as soon as its last key comes, so it cannot also be the start of a longer binding: Ctrl-X bound to [editClearScreen] and Ctrl-X Ctrl-E cannot both work. The same holds when its keys come in the middle of the longer binding, as [r';' r'r'] does in [r'x' r';' r'r' r'q']. When two bindings conflict like this, the newer one wins, and the older one is kept but never fires. Since init.msh runs after the defaults are added, your bindings win over them. Edits never conflict: Space can expand abbreviations and [r' ' r' '] can still be bound.

A sequence has no time limit unless its binding gives one. With within: 150, v, a pause, and l types vl. With idleBefore: 150, the vl in devlog does not fire when typed at speed. Fast typists' keys come about 120 ms apart, so for a pair of letters, 150 for both is a reasonable start. Over ssh, times under about 100 ms are not reliable. Choosing keys that do not occur in what you type is surer than any time.

A binding is in one of two keymaps, an EditMode. modeInsert is the normal one, and the mode of a binding that does not give one. modeComplete is the one while Tab cycles through several matches: a key bound there does what it does there, and any other key stops cycling and acts as in modeInsert.

The abbreviation keys are bindings like the others, so any key can be made to expand abbreviations, and a pair of keys can be replaced as you type, the way an abbreviation is replaced at Space: 

{keys: [r'|' r'|'], action: ['| less' editInsert] bindingOps} bindingAdd
{keys: [r','], action: [editExpandAbbr editSelfInsert] bindingOps} bindingAdd

Adding, removing and listing

bindingAdd replaces a binding with the same keys in the same mode. bindingErase takes a list of keys and removes the bindings with those keys, in both modes, defaults included; a key that types text then types it again, and any other key does nothing. bindingList gives every binding, oldest first, so the defaults come first. mode is always present.

None of these fails on a value of the right type. A binding that can never fire is added but stays inert, and the interactive shell prints a warning about it: one with no keys or more than 8, a within or idleBefore that is not more than 0, an operation after editAccept or editExit, or one that a newer binding conflicts with.

These types and their members are built in, so their names cannot be used for your own types, members or definitions.

File manager § Back to top

mshell has a file manager built in: the entries of a directory on the left, a preview of the one under the cursor on the right. Ctrl-O opens it from the shell, and when you quit with q, the shell changes to the directory shown. In a script, mshFileManager opens it, starting in the directory it is given. msh fm opens it from any shell, starting in the directory given, or the working directory, and prints the directory you quit in, so cd "$(msh fm)" follows it.

Its keys are bindings, as the shell's are, in a table of their own. init.msh adds to it with fmBindingAdd, which takes an FmBinding. msh fm loads the standard library and init.msh before it starts, as a script does, so your bindings work there too. What they print goes to standard error, so the directory is the only thing msh fm prints. 

# Go home, or to the repositories, with g h and g r. They join g g in the popup.
{keys: [r'g' r'h'], action: [~ fmCd] fmOps, description: 'home'} fmBindingAdd
{keys: [r'g' r'r'], action: [~/repos fmCd] fmOps, description: 'repositories'} fmBindingAdd

# lazygit in the directory shown.
{keys: [r'L'], action: [([lazygit];) fmRun] fmOps, description: 'lazygit'} fmBindingAdd

# Search for TODO in one key.
{keys: [r't' keyAlt], action: [fmPromptSearch fmPrompt 'TODO' editInsert fmLineAccept] fmOps} fmBindingAdd

# Half a screen with Ctrl-D and Ctrl-U, as in Vim.
{keys: [r'd' keyCtrl], action: [50.0 fmPercent fmDownBy] fmOps, description: 'half a page down'} fmBindingAdd
{keys: [r'u' keyCtrl], action: [50.0 fmPercent fmUpBy] fmOps, description: 'half a page up'} fmBindingAdd
Key Type Description
keys [Key] The keys to press, in order, at most 8, as for the shell's bindings.
action FmAction What the keys do: fmOps FmProgram, a fixed program, or fmFunc (FmState -- Maybe[FmProgram]), a quotation that is given the file manager's state and returns the program to run, or none to decline.
mode (optional) FmMode The keymap the binding is in (below); fmModeNormal when not given.
within (optional) int The longest time, in milliseconds, between two of its keys.
idleBefore (optional) int The shortest time, in milliseconds, with no key before its first key.
description (optional) str What the binding does, shown in the list of keys that can follow a key, and on the help screen.

An FmProgram is a list of FmOp and EditOp values, [FmOp | EditOp]: the prompt line is edited with the shell's line edits, so editDeleteWordLeft means the same thing in both places. A list written in place is a program; a list kept in a variable as [EditOp] is not, and is made one with as FmProgram.

Modes

The file manager has three keymaps, an FmMode.

  • fmModeNormal: browsing. A key is a command, and a key with no binding does nothing.
  • fmModeInsert: the prompt line at the bottom, for search, rename, and prompts of your own. Keys edit the line, and a key that types text and has no binding types it.
  • fmModeHelp: the help screen, which lists every binding.

A program can cross modes: fmPrompt switches to the prompt line, fmLineAccept and fmLineCancel back, and fmHelp and fmHelpClose to the help screen and back. [fmPromptSearch fmPrompt 'TODO' editInsert fmLineAccept] searches for TODO on one key. fmBindingAdd follows the mode through a program, and an operation that cannot run where it stands makes the binding inert: [fmDown editLeft] never fires.

In fmModeInsert, with the shell's line edits: editInsert, editSelfInsert, editSetLine, editLeft, editRight, editWordLeft, editWordRight, editLineStart, editLineEnd, editBackspace, editDelete, editDeleteWordLeft, editDeleteToStart and editDeleteToEnd. A word ends at a space or a ., so in report.final.pdf, with the cursor before .pdf, Ctrl-W deletes final.
fmLineAccept Close the line, and do what its prompt does with it.
fmLineCancel Close the line, and do nothing.
In fmModeHelp, with the moves above, which scroll the help.
fmHelpClose Close the help, and go back to the listing as it was.
In any mode.
fmRun ( -- ) Run the quotation with the terminal (below).
fmRunWait ( -- ) The same, and then wait for a key, so what it printed can be read.
fmRunOps (FmState -- Maybe[FmProgram]) The same as fmRun, but the quotation is given the state, and the program it returns runs afterwards.
fmMessage str Show the text at the bottom until the next key.
fmQuit Quit; the shell changes to the directory shown, and msh fm prints it. It must be the last operation.
fmQuitNoCd Quit and leave the directory as it was: msh fm prints the directory it started in. It must be the last operation.

The operations of a program run in order, and the screen is drawn once after the last. When an operation finds itself in a mode it cannot run in, as an editInsert after a rename prompt that did not open in an empty directory, the program stops there, and a message names it. The operations that need a real directory do nothing on Windows' list of drives.

The selection

Space selects the entry under the cursor and moves down, v inverts the selection and u clears it. Selected entries are marked with a *, and the top row says how many there are. Entries stay selected when you change directory, so entries from several directories can be cut or copied together. fmCut, fmCopy, fmTrash, the yanks and fmOpenEditor act on every selected entry when there are any, or else on the entry under the cursor, and then clear the selection. A selected entry that no longer exists is left out, and the message after says how many were. The selection lasts while the file manager runs. The file-manager clipboard is a file, shared by every file manager you open, until it is pasted or cleared.

Prompts

fmPrompt opens the prompt line at the bottom, in fmModeInsert. What it starts as, and what Enter does, come from the FmPrompt.

Prompt Opens with On fmLineAccept
fmPromptSearch / and an empty line; the matches are highlighted as you type Put the cursor on the first match at or after it. Case does not matter.
fmPromptRename rename: and the name of the entry under the cursor, the cursor before its extension Rename the entry, and put the cursor on it.
fmPromptAsk str str (str FmState -- Maybe[FmProgram]) The first string as the label, the second as the line, the cursor at its end Run the quotation with the line and the state, and then the program it returns.

The line holds at most 4096 bytes, so any path fits. An edit that would make it longer is not done, and a message says so. The quotation of fmPromptAsk runs after the line has closed, so the state it is given is in fmModeNormal, and like a fmFunc quotation it runs on its own stack and is stopped after 1 second. Anything slow or interactive goes in the program it returns, as an fmRun or fmRunWait: 

# A new directory, named at a prompt, with the cursor put on it.
def newDir (str FmState -- new Maybe[FmProgram])
    name!, s!
    @name '' = if
        none
    else
        $"{@s :dir?}/{@name}" mkdir
        [fmReload @name fmCursorTo] just
    end
end
{keys: [r'a'], action: ['New directory: ' '' (newDir) fmPromptAsk fmPrompt] fmOps, description: 'new directory'} fmBindingAdd

# A shell command in the directory shown; its output stays until a key is pressed.
def shellCommand (str FmState -- new Maybe[FmProgram])
    drop cmd!
    [([sh -c @cmd];) fmRunWait] just
end
{keys: [r'!'], action: ['sh: ' '' (shellCommand) fmPromptAsk fmPrompt] fmOps, description: 'shell command'} fmBindingAdd

Running commands

fmRun gives the terminal to its quotation, as editRun does in the shell: the quotation runs in the foreground, on its own empty stack, with no time limit, in the directory shown, and its output goes to the terminal, under msh fm too. When it ends, the file manager takes the screen back, reads the directory again, and keeps the cursor on the same entry. If the quotation changed directory, the file manager shows the new one. If it failed, its error is printed, and the file manager waits for Enter before drawing over it. fmRunWait also waits for any key when it succeeds, and fmRunOps runs the program its quotation returns. The mode and the prompt line are kept, so fmRun pressed while renaming comes back to the same line. exit in the quotation ends the file manager, and then does what exit does anywhere.

Quotations

A fmFunc quotation, and the quotations of fmPromptAsk and fmRunOps, are given an FmState. A fmFunc returns just the program to run, or none to decline, and runs as a shell binding's quotation does: on its own stack, stopped after 1 second, with what it prints not shown, and a failure shown at the bottom.

Key Type Description
dir str The directory shown, absolute.
current Maybe[str] The entry under the cursor, absolute, or none in an empty directory.
selected [str] The selected entries, absolute, in the order they were selected.
mode FmMode The mode the keys were pressed in.
line Maybe[FmLine] In fmModeInsert, the prompt line: {prompt: FmPrompt, before: str, after: str}, split at its cursor. A binding can match on prompt to act only in search, or only in a prompt of its own.
keys [Key] The keys that ran the binding. 
# Run the current entry with Enter when it is an mshell script; anything else opens as before.
def runScript (FmState -- new Maybe[FmProgram])
    :current? match
        just f : @f '.msh' endsWith if [([msh @f];) fmRun] else [fmOpen] end just,
        none : none,
    end
end
{keys: [keyEnter], action: (runScript) fmFunc} fmBindingAdd

# The root of the git repository, found by a command.
def gitRoot (FmState -- new Maybe[FmProgram])
    :dir? d!
    [git -C @d rev-parse --show-toplevel] * ? code! out!
    @code 0 = if [@out chomp fmCd] just else ['Not in a git repository' fmMessage] just end
end
{keys: [r'g' r'R'], action: [(gitRoot) fmRunOps] fmOps, description: 'git root'} fmBindingAdd

# Zip the selected entries into archive.zip in the directory shown.
def zipSelected (FmState -- new Maybe[FmProgram])
    :selected? files!
    @files len 0 = if
        ['Nothing selected' fmMessage] just
    else
        [(['zip' '-r' 'archive.zip'] @files + ;) fmRunWait fmSelectionClear] just
    end
end
{keys: [r'z' r'a'], action: (zipSelected) fmFunc, description: 'zip the selection'} fmBindingAdd

# Today's date at the cursor in the prompt line.
{keys: [r'd' keyAlt], action: (drop [now isoDateFmt editInsert] just) fmFunc, mode: fmModeInsert} fmBindingAdd

runScript binds Enter in fmModeNormal, so it replaces the default binding of Enter, and returns [fmOpen] for any other file, to do what that binding did. It could not decline instead: a declined binding leaves the key to its own action, and in fmModeNormal a key has none. Bindings are tested like any other definition, with an FmState made by hand: 

{dir: '/tmp', current: '/tmp/a.msh' just, selected: [], mode: fmModeNormal, line: none, keys: [keyEnter]} runScript str wl

Sequences, the popup, and help

Sequences work as they do in the shell, with the cursor in place of the line: a move that begins a longer binding moves at once, and is taken back when the longer binding completes. Any other operation, and any quotation, runs as soon as its last key comes, so it cannot also be the start of a longer binding, and of two bindings that conflict, the newer wins and the older is kept but never fires. Most of the file manager's keys are like that, so this comes up more often than in the shell. d is cut, and adding d d makes d inert, with a warning every time init.msh runs. To replace a key with a sequence, erase it first: 

# ranger's keys for cut and trash. Erasing first keeps d from being reported as inert.
[r'd'] fmBindingErase
[r'x'] fmBindingErase
{keys: [r'd' r'd'], action: [fmCut] fmOps, description: 'cut'} fmBindingAdd
{keys: [r'd' r'D'], action: [fmTrash] fmOps, description: 'move to the trash'} fmBindingAdd

While keys wait for more, as after y or g, a box lists the bindings that can follow, with their descriptions, or their operations when they have none. It waits for the next key with no time limit. A key that does not continue the sequence closes it and acts on its own, so Escape closes it and does nothing else.

? shows the help screen: every binding in force, for each mode, and then every binding that does not fire, with the reason. It is the one place msh fm shows why a binding does nothing. It scrolls with the keys that move the cursor, and q, Escape or ? closes it.

Pastes and questions

A paste never runs keys. In the prompt line it goes in at the cursor as one edit, once line breaks at its end are dropped; it is refused whole, with a message saying why, if it holds any other control character or would make the line too long. Anywhere else it is refused, and the bottom row says so.

Three things ask before they act: fmTrash (y confirms), fmPaste when a name exists already (o overwrites, v adds a version number), and the bookmarks, which ask for the bookmark's key. A question shows its answers and reads one key, which reaches no binding. Escape, or any key it does not offer, is no. Their answers are fixed; what you can change is the key that asks.

Adding, removing and listing

fmBindingAdd, fmBindingErase and fmBindingList work as bindingAdd, bindingErase and bindingList do, over the file manager's table. A binding that can never fire is kept, listed, inert and shown on the help screen, and the interactive shell prints a warning about it: for the shell's reasons, and for an operation that cannot run in the mode it stands in (any EditOp that is not a line edit, in every mode), an operation after fmQuit or fmQuitNoCd, or a distance of 0 or less. The prompt line has its own keymap, apart from the shell's line, so a key you change in the shell is not changed there: bind it in both if you want it in both.

GitHub Actions § Back to top

To use mshell in GitHub Actions workflows, use the official action: 

steps:
  - uses: mitchpaulus/mshell@v0.12.0
  - run: msh script.msh

To pin a specific version: 

steps:
  - uses: mitchpaulus/mshell@v0.12.0
    with:
      version: v0.12.0
  - run: msh script.msh

The action downloads the pre-built binary for the runner platform and installs the matching startup files automatically.

To use a build that has not been released yet, pass a commit SHA or branch name as the version. Anything that is not latest and does not start with v is treated as a git ref: the action clones the repository at that ref and builds from source with Go (installed automatically via actions/setup-go). 

steps:
  - uses: mitchpaulus/mshell@main
    with:
      version: a087dc2f
  - run: msh script.msh

Editor Support § Back to top

Syntax highlighting and editor integrations are available for common editors:

  • VS Code Extension: mshell extension
  • Sublime Text: msh.sublime-syntax
  • Notepad++: user-defined language files (light and dark)
  • Vim/Neovim: mshell-vim

Shell completions for using mshell within a different shell can be generated by the CLI: 

# bash
source <(msh completions bash)

# fish
msh completions fish | source

# elvish
msh completions elvish | eval

# nushell
msh completions nushell | save --force $"($nu.default-config-dir)/completions/msh.nu"
use $"($nu.default-config-dir)/completions/msh.nu" *

A language server is bundled with the CLI, providing builtin hover information, completion on @ variables and $ environment variables, scope-aware variable renaming, goto declaration of type aliases, enums, enum members and definitions, and a code action that single-quotes every bare literal in the parsed list value containing the cursor. Environment variable completion draws from the actual process environment as well as any environment variables already referenced in the current file.
